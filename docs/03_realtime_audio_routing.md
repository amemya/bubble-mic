# 03. マイク選定ガイド・Discord接続・検証ロードマップ

## 1. 【ハードウェア対策】2人部屋VCに最適なマイク選定と配置ガイド

ソフトウェア処理（BubbleMic）の性能を最大限に引き出す上で、マイクの指向性と口元からの距離は極めて重要です。将来マイクを買い替える際（または現在のマイクを配置する際）は、以下の音響物理原則に従うことで、**机置き（口から40cm）のマイクと比較して、物理段階の信号対妨害音比（SIR）を `20〜25 dB` 改善できます**。

### 1.1 室内音響の現実と「単一指向性マイクの口元配置」の優位性

6畳〜8畳程度の居室では、音源から `0.5〜1.0m` 以上離れると直接音よりも部屋の壁・天井からの**残響音（反射音）**が支配的になります（臨界距離）。そのため、2m離れた同居人の声は自由空間の逆二乗則（32dB）ほどは減衰せず、また指向性マイクが残響音に対して稼げる減衰量も指向性係数（カーディオイドで約 `4.8 dB`、ハイパーカーディオイドで約 `6 dB`）に留まります。

それでもなお、**「机の上に置いたマイク（口から40cm）」を「口元5cm（またはブームマイクで2〜3cm）に寄せた単一指向性マイク」に変える効果は絶大**です。

* **自分の声だけが `+18 dB` 大きくなる**: 自分の口元（5cm〜40cm）は臨界距離の内側（直接音領域）にあるため、距離を40cmから5cm（1/8）に近づけると、逆二乗則どおり自分の声や咳の音圧だけが **`+18 dB`（約8倍）** 跳ね上がります。
* **指向性による減衰（`+5〜7 dB`）**: 同居人からの直接音と初期反射音を指向性の死角（ヌルポイント）で削ることで、さらに `5〜7 dB` のマージンが加わります。
* **机置き比で合計 `23〜25 dB` の物理SIR改善**: これに加え、単一指向性マイクを口元で使うと**近接効果（口元の音だけ100〜250Hzの低域が強調される現象）**が働くため、DNNおよび補助ゲートが「口元の生体音」と「遠くの同居人の声」を識別する有力な手がかりになります。

### 1.2 指向性別のマイクの向き（死角・ヌルポイントの合わせ方）

マイクの指向性によって「一番音を拾わない角度（ヌルポイント）」が異なります。同居人のいる方向に合わせてマイクの角度を調整してください。

| 指向性の種類 | 最も音を拾わない死角（ヌルポイント） | 2人部屋での正しいマイクの向け方 |
| :--- | :---: | :--- |
| **カーディオイド**<br>（単一指向性） | **真後ろ（`180°`）** | マイクの正面（`0°`）を自分の口に向け、**マイクの真後ろ（お尻側）が同居人のいる方向**を向くように配置する。 |
| **ハイパーカーディオイド**<br>（超単一指向性） | **斜め後ろ（約 `110° 〜 120°`）**<br>※真後ろ（`180°`）には少し感度の山（バックローブ）がある | マイクの真後ろを同居人に向けてはいけない。**同居人のデスクやベッドがマイクの斜め後ろ（`110°〜120°`）の死角に入るように**角度を振って配置する。 |

### 1.3 おすすめのマイク候補（スタンド型 vs ブームマイク型の比較）

※ 購入前には必ずメーカー公式仕様で指向性（単一指向性 / ハイパーカーディオイド）と最新の価格をご確認ください。

#### A. マイクアーム＋USBダイナミックマイク（高音質・デスク固定派）
コンデンサーマイクではなくダイナミックマイクを選び、**必ずマイクアーム（2,000〜3,000円程度）を併用して口元5cmに配置**します（アームを使うことで机からのキーボード打鍵振動も遮断できます）。
* *運用上の注意点*: 口元5cm配置では、姿勢を崩して口とマイクの距離が `5cm → 10cm` に離れるだけで自分の声の入力レベルが `-6 dB` 変化します。そのため、次に紹介するヘッドセット装着型（B）と比べると、喋る時の姿勢（マイクとの距離）をある程度一定に保つ意識が必要です。

* **Audio-Technica AT2040USB**（またはXLR版 AT2040）
  * **ハイパーカーディオイド（超単一指向性）**のダイナミックマイク。斜め後ろ（約110°〜120°）に同居人が位置するレイアウトで高い遮音性を発揮します。
* **Samson Q2U** または **Audio-Technica ATR2100x-USB**
  * **カーディオイド（単一指向性）**の定番USB/XLRダイナミックマイク。比較的手頃な価格で導入でき、真後ろに同居人がいるレイアウトに向いています。
* **Shure MV7+**（または MV7X）
  * ボイスアイソレーション（近接集音）に特化した定番ダイナミックマイク。

#### B. 単一指向性ブームマイク（距離固定・アルゴリズム相性最良）
ヘッドホンや頭部にマイクが固定されるため、**椅子にもたれかかったり首を動かしたりしても「口とマイクの距離（2〜3cm）」が絶対に変わらない**という非常に大きな利点があります。自分の発話レベル $L_{\text{self}}$ と近接効果が常に一定に保たれるため、BubbleMicのDNNおよび補助ゲートの閾値判定と最も相性が良い方式です。
**※必ず「無指向性（オムニ）」ではなく「単一指向性（Uni-directional / Cardioid）」のモデルを選んでください。**

* **Antlion Audio ModMic Uni 2**
  * 手持ちの好きなヘッドホンやイヤホンに磁石で装着できる外付けブームマイク。無指向性モデルではなく、必ず**「Uni（単一指向性ノイズキャンセリング）」**モデルを選択します。
* **単一指向性ブームマイク搭載ヘッドセット**（Audio-Technica ATH-GDL3 / GL3、EPOS H6PRO 等）
  * ヘッドセット一体型を選ぶ場合も、メーカー公式仕様でブームマイクが「単一指向性（ハイパーカーディオイド／カーディオイド）」であることを確認して選定します。

## 2. OS上のオーディオルーティングとDiscord設定

```text
[物理マイク (口元固定)]
       │ (48kHz, Buffer: 256~512 samples)
       ▼
┌────────────────────────────────────────────────────────┐
│ BubbleMic Realtime Daemon                              │
│  ├─ Main Path: 自分専用Fine-tuned DNN (Y_dnn)          │
│  ├─ Sidechain Path: 汎用NR (Y_nr) + 過剰抑制検知ゲート │
│  └─ 複素スペクトル線形ブレンド & iSTFT                 │
└────────────────────────────────────────────────────────┘
       │
       ▼
[仮想オーディオデバイス: BlackHole 2ch (macOS) / VB-Cable (Win)]
       │
       ▼
[Discord 入力デバイス]
```

### Discord側の推奨設定
* **ノイズ抑制 (Krisp)**: **OFF（なし）**（BubbleMic側で打鍵音・環境音・同居人声を除去済みのため。Krispを二重にかけると伸びやため息が削られる原因になります）
* **入力感度**: **手動（`-50 dB` 付近の敏感側）**（Discord側のVADゲートで伸びやため息の語尾が切れるのを防ぐ）
* **自動ゲイン制御 (AGC)**: **OFF**

## 3. 段階的検証ロードマップ（全5フェーズ）

いきなりDNNを学習する前に、まずは**「半実録テストセット」の作成とベースライン測定**を行い、既存のノイズゲートや素のノイキャンだけでどこまで解けて、何が課題として残るのかを数値で切り分けます。

### Phase 1: マイク配置の固定と「半実録テストセット」の録音（1〜2時間）
マイクと口元の距離を本番運用と同じ位置に固定し、`02_model_and_dataset.md §4` の手順に従って以下の評価専用音声を**別々に**録音します。
1. **自分の通常発話のみ**（3〜5分、静かな環境）
2. **自分の非言語音声（咳払い・伸び・あくび・笑い・ため息）のみ**（3〜5分、静かな環境）
3. **同居人が友人と会話・談笑している時の放置録音＋手元の打鍵・クリック音**（5〜10分、自分は無言。※学習用とは別セッションのもの）
* これらをデジタル加算した `semi_real_mix.wav`（定量指標算出用）と、実際に同時に喋って録音した `live_room_mix.wav`（最終聴感確認用）を用意します。

### Phase 2: ベースライン測定と素のノイキャン・音量差の確認（半日）
一切の追加学習を行わず、以下の2つの既存手法を `semi_real_mix.wav` に通して3つの定量指標（無言時相対リーク減衰、非言語音エネルギー保持率、同時発話SI-SDR）を測定します。
* **Baseline 1**: 閾値を調整したエキスパンダー（ノイズゲート）のみ
* **Baseline 2**: 素の GTCRN（48K） / DeepFilterNet3（2.1M） ＋ エキスパンダー
  * *ここでの重要な3つの確認ポイント*:
    1. 自分無言時の打鍵音や同居人の声は Baseline 2 でどこまで落ちるか。
    2. **素の GTCRN / DeepFilterNet3 が、自分の咳・伸び・ため息をどれだけ残すか（Sidechain Path のブレンド源 $Y_{\text{nr}}$ としてそのまま使えるか、減衰上限 `atten_lim` を緩める必要があるか）**を数値で確認する。
    3. **ゲート閾値の根拠確認**: 自分の通常発話の平均RMSレベル $L_{\text{self}}$ に対して、放置録音中の「同居人の大笑いのピークレベル」が何 dB 低いかを実測し、`10 dB` 以上のマージンがあることを確認して補助ゲートの閾値（$L_{\text{self}} - 10\text{ dB}$）を確定する。

### Phase 3: 放置録音による同居人データ収集とデータセット構築（1〜2日）
1. 同居人が部屋で友人と喋っている時にマイクを放置録音し、本物の背景会話データ（Noise ①、30分〜数時間）を集める（高振幅閾値で自分の咳等が混ざった箇所のみ機械的に除外）。
2. 自分の通常発話（20〜30分）、非言語音声（5〜10分）、デスクの打鍵・クリック音（5〜10分）、および未知話者水増し用の実測RIRを収録する。
   * あわせて、収録した自分の非言語音声（特に長い「伸び」「あくび」）の持続時間分布（95〜99パーセンタイル長、目安 `2.5〜3.0秒`）を測定し、補助ゲートの最大開放時間リミッターの値を決定する。
3. 5パターン（放置録音同時30%・実測RIR未知話者同時15%・非言語20%・無言25%・クリーン10%）の動的ミキシングスクリプトを作成する（放置録音は実レベルの `±6 dB` 以内で合成）。

### Phase 4: Main Path DNN の Fine-tuning と定量評価（2〜4日）
1. **Step 1 (GTCRN 48K)**: まずはPyTorch単体で高速に学習が回る公開学習済み GTCRN（48K）で Fine-tuning を行い、損失関数の重み（$\lambda_{\text{nv}}, \lambda_{\text{mute}}$）とデータ配合（ドライな他人声を `0%` にするか `5%` だけ混ぜるかの比較含む）を最適化する。
2. **Step 2 (DeepFilterNet3 2.1M)**: パイプラインとデータ配合が固まったら（または48Kモデルで分離容量の限界が見えたら）、48kHzフルバンド対応の公開学習済み DeepFilterNet3（2.1M）を Fine-tuning する。
3. `semi_real_mix.wav` で Baseline 1/2 と数値を比較し、目標値（無言時相対リーク `< -40 dB`、非言語音保持 `-1.5 dB` 以内、SI-SDR改善 `+10 dB` 以上）の達成および補助ゲート（$\alpha(t)$）による長い伸び・あくびの救済効果を確認する。

### Phase 5: リアルタイム仮想マイク化とDiscord実戦投入（1日）
`物理マイク -> BubbleMic -> BlackHole 2ch -> Discord` を繋ぎ、ループバック実測遅延（目標 `< 75 ms`）とVCでの聴感を確認します。
