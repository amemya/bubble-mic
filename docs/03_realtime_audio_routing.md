# 03. マイク選定ガイド・Discord接続・検証ロードマップ

## 1. 【ハードウェア対策】2人部屋VCに最適なマイク選定と配置ガイド

ソフトウェア処理（BubbleMic）の性能を最大限に引き出す上で、マイクの指向性と口元からの距離は極めて重要です。将来マイクを買い替える際（または現在のマイクを配置する際）は、以下の音響物理原則に従うことで、**マイクに入った時点（物理段階）で同居人の声を `20〜25 dB` 以上小さくできます**。

### 1.1 室内音響の現実と「単一指向性ダイナミック＋口元5cm」の優位性

6畳〜8畳程度の居室では、音源から `0.5〜1.0m` 以上離れると直接音よりも部屋の壁・天井からの**残響音（反射音）**が支配的になります（臨界距離）。そのため、2m離れた同居人の声は自由空間の逆二乗則（32dB）ほどは減衰せず、また指向性マイクが残響音に対して稼げる減衰量も指向性係数（カーディオイドで約 `4.8 dB`、ハイパーカーディオイドで約 `6 dB`）に留まります。

それでもなお、**「机の上に置いたマイク（口から40cm）」を「マイクアームで口元5cmに寄せた単一指向性マイク」に変える効果は絶大**です。

* **自分の声だけが `+18 dB` 大きくなる**: 自分の口元（5cm〜40cm）は臨界距離の内側（直接音領域）にあるため、距離を40cmから5cm（1/8）に近づけると、逆二乗則どおり自分の声や咳の音圧だけが **`+18 dB`（約8倍）** 跳ね上がります。
* **指向性による減衰（`+5〜10 dB`）**: 同居人からの直接音と初期反射音を指向性の死角（ヌルポイント）で削ることで、さらに `5〜10 dB` のマージンが加わります。
* **合計 `23〜28 dB` の物理SIR（信号対妨害音比）向上**: これに加え、単一指向性マイクを口元5cmで使うと**近接効果（口元の音だけ100〜250Hzの低域が強調される現象）**が働くため、DNNが「口元の生体音」と「遠くの同居人の声」を識別する強い手がかりになります。

### 1.2 指向性別のマイクの向き（死角・ヌルポイントの合わせ方）

マイクの指向性によって「一番音を拾わない角度（ヌルポイント）」が異なります。同居人のいる方向に合わせてマイクの角度を調整してください。

| 指向性の種類 | 最も音を拾わない死角（ヌルポイント） | 2人部屋での正しいマイクの向け方 |
| :--- | :---: | :--- |
| **カーディオイド**<br>（単一指向性） | **真後ろ（`180°`）** | マイクの正面（`0°`）を自分の口に向け、**マイクの真後ろ（お尻側）が同居人のいる方向**を向くようにアームを配置する。 |
| **ハイパーカーディオイド**<br>（超単一指向性） | **斜め後ろ（約 `110° 〜 120°`）**<br>※真後ろ（`180°`）には少し感度の山（バックローブ）がある | マイクの真後ろを同居人に向けてはいけない。**同居人のデスクやベッドがマイクの斜め後ろ（`110°〜120°`）の死角に入るように**角度を振って配置する。 |

### 1.3 おすすめのマイク候補

※ 購入前には必ずメーカー公式仕様で指向性（単一指向性 / ハイパーカーディオイド）と最新の価格をご確認ください。

#### A. マイクアーム＋USBダイナミックマイク（最もおすすめ）
コンデンサーマイクではなくダイナミックマイクを選び、**必ずマイクアーム（2,000〜3,000円程度）を併用して口元5cmに配置**します（アームを使うことで机からのキーボード打鍵振動も遮断できます）。

* **Audio-Technica AT2040USB**（またはXLR版 AT2040）
  * **ハイパーカーディオイド（超単一指向性）**のダイナミックマイク。斜め後ろ（約110°〜120°）に同居人が位置するレイアウトで圧倒的な遮音性を発揮します。
* **Samson Q2U** または **Audio-Technica ATR2100x-USB**
  * **カーディオイド（単一指向性）**の定番USB/XLRダイナミックマイク。比較的手頃な価格で導入でき、真後ろに同居人がいるレイアウトに向いています。
* **Shure MV7+**（または MV7X）
  * ボイスアイソレーション（近接集音）に特化した定番ダイナミックマイク。

#### B. 単一指向性ブームマイク（口元2〜3cmに常時固定したい場合）
姿勢を変えても口とマイクの距離（2〜3cm）が絶対に変わらないため、近接効果と音圧が常に一定になり、BubbleMicの学習・推論と非常に相性が良い方式です。**※必ず「無指向性（オムニ）」ではなく「単一指向性（Uni-directional / Cardioid）」のモデルを選んでください。**

* **Antlion Audio ModMic Uni 2**
  * 手持ちの好きなヘッドホンやイヤホンに磁石で装着できる外付けブームマイク。無指向性モデルではなく、必ず**「Uni（単一指向性ノイズキャンセリング）」**モデルを選択します。
* **単一指向性ブームマイク搭載ヘッドセット**（Audio-Technica ATH-GDL3 / GL3、EPOS H6PRO 等）
  * ヘッドセット一体型を選ぶ場合も、マイク仕様が「単一指向性（ハイパーカーディオイド／カーディオイド）」であることを確認して選定します。

## 2. OS上のオーディオルーティングとDiscord設定

```text
[物理マイク (口元5cm固定)]
       │ (48kHz, Buffer: 256~512 samples)
       ▼
┌────────────────────────────────────────────────────────┐
│ BubbleMic Realtime Daemon                              │
│  ├─ Main Path: 自分専用Fine-tuned DNN (Y_dnn)          │
│  ├─ Sidechain Path: 汎用NR (Y_nr) + 過剰抑制検知ゲート │
│  └─ 複素スペクトル線形ブレンド & iSTFT                 │
└────────────────────────────────────────────────────────┘
       │
       ▼
[仮想オーディオデバイス: BlackHole 2ch (macOS) / VB-Cable (Win)]
       │
       ▼
[Discord 入力デバイス]
```

### Discord側の推奨設定
* **ノイズ抑制 (Krisp)**: **OFF（なし）**（BubbleMic側で打鍵音・環境音・同居人声を除去済みのため。Krispを二重にかけると伸びやため息が削られる原因になります）
* **入力感度**: **手動（`-50 dB` 付近の敏感側）**（Discord側のVADゲートで伸びやため息の語尾が切れるのを防ぐ）
* **自動ゲイン制御 (AGC)**: **OFF**

## 3. 段階的検証ロードマップ（全5フェーズ）

いきなりDNNを学習する前に、まずは**「半実録テストセット」の作成とベースライン測定**を行い、既存のノイズゲートや素のノイキャンだけでどこまで解けて、何が課題として残るのかを数値で切り分けます。

### Phase 1: マイク配置の固定と「半実録テストセット」の録音（1時間）
マイクと口元の距離を本番運用と同じ位置に固定し、`02_model_and_dataset.md §5` の手順に従って以下のテスト用音声を**別々に**録音します。
1. **自分の通常発話のみ**（60秒、スピーカー停止）
2. **自分の非言語音声（咳払い・伸び・あくび・笑い・ため息）のみ**（60秒、スピーカー停止）
3. **同居人位置のスピーカー会話＋手元の激しい打鍵・クリック音のみ**（120秒、自分は無言）
* これらをデジタル加算した `semi_real_mix.wav`（定量指標算出用）と、実際に同時に鳴らして録音した `live_room_mix.wav`（最終聴感確認用）の2種類を用意します。

### Phase 2: ベースライン測定と素のノイキャンの挙動確認（半日）
一切の追加学習を行わず、以下の2つの既存手法を `semi_real_mix.wav` に通して3つの定量指標（無言時相対リーク減衰、非言語音エネルギー保持率、同時発話SI-SDR）を測定します。
* **Baseline 1**: 閾値を調整したエキスパンダー（ノイズゲート）のみ
* **Baseline 2**: 素の GTCRN / DeepFilterNet3 ＋ エキスパンダー
  * *ここでの重要な確認ポイント*:
    1. 自分無言時の打鍵音や同居人の声は Baseline 2 でどこまで落ちるか。
    2. **素の GTCRN / DeepFilterNet3 が、自分の咳・伸び・ため息をどれだけ残すか（Sidechain Path のブレンド源 $Y_{\text{nr}}$ としてそのまま使えるか、減衰上限 `atten_lim` を緩める必要があるか）**を数値で確認します。

### Phase 3: 実部屋RIR・自分データの収録とデータセット構築（半日）
1. 自分の通常発話（20〜30分）、非言語音声（3〜5分）、デスクの打鍵・クリック音（5〜10分）を録音。
2. 同居人位置のスピーカーからスイープ信号（実測RIR取得用）およびコーパス音声・他人の笑い声/咳を再生して録音。
3. 5パターン（遠方同時30%・近接同時15%・非言語20%・無言25%・クリーン10%）の動的ミキシングスクリプトを作成。

### Phase 4: Main Path DNN の Fine-tuning と定量評価（2〜4日）
1. **Step 1 (GTCRN)**: まずはPyTorch単体で高速に学習が回る GTCRN（48K → 必要に応じて Large 350K）で Fine-tuning を行い、損失関数の重み（$\lambda_{\text{nv}}, \lambda_{\text{mute}}$）とデータ配合を最適化する。
2. **Step 2 (DeepFilterNet3)**: パイプラインとデータ配合が固まったら、48kHzフルバンド対応の DeepFilterNet3 用データセット（HDF5）を生成して本命モデルを Fine-tuning する。
3. `semi_real_mix.wav` で Baseline 1/2 と数値を比較し、目標値（無言時相対リーク `< -40 dB`、非言語音保持 `-1.5 dB` 以内、SI-SDR改善 `+10 dB` 以上）の達成および補助ゲート（$\alpha(t)$）の救済効果を確認する。

### Phase 5: リアルタイム仮想マイク化とDiscord実戦投入（1日）
`物理マイク -> BubbleMic -> BlackHole 2ch -> Discord` を繋ぎ、ループバック実測遅延（目標 `< 75 ms`）とVCでの聴感を確認します。
