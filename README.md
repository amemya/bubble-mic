# BubbleMic (`~/bubble-mic`)

> **「口元の音響バブル（自分の発話＋咳・伸び・笑いなどの非言語音声）だけを抽出し、打鍵音およびバブル外の同居人・来客の会話を遮断するリアルタイムVCフィルタ」**

## 1. 背景と解決したい課題

2人部屋の寮などの共有空間でボイスチャット（Discord等）をする際、同居人やその友人の話し声が自分のマイクに乗ってしまう問題があります。

| 既存アプローチ | 挙動 | 寮の2人部屋VCにおける課題 |
| :--- | :--- | :--- |
| **汎用AIノイキャン**<br>(Discord Krisp / RNNoise) | 「人間の声」全般を残し、打鍵音や環境音のみを消す | 同居人や友人の話し声・笑い声も「人間の声」としてそのままクリアに通してしまう。 |
| **従来の目標話者抽出 (TSE)**<br>(VoiceFilter / SpEx+ 等) | 事前登録した「自分の声紋ベクトル」と一致する音だけを残す | 母音・通常発話に基づく声紋ベクトルと一致しない**非言語音声（咳払い、伸び、あくび、笑い声、息遣い）がすべてノイズとして消去**され、VCでのリアクションが不自然になる。 |

### スコープ定義とフェイルセーフ原則（優先順位の割り切り）
* **消去対象とする状況**: 同居人や来客が自分のデスクから離れた位置（`1.2m〜3.5m` 先の同居人デスクやベッド等）で会話・談笑・咳払いなどをしている状況、および自分の手元のキーボード打鍵音・マウスクリック音。
* **スコープ外（手動ミュート運用）**: 同居人や友人が自分のデスクの真横（数十cm）まで近づいて直接話しかけてきた場合は、そもそもVCを継続する状況ではないためDiscord側のマイクミュートで対応します。
* **フェイルセーフ原則と段階的アプローチ（優先度 1 → 2 → 3）**:
  * **【優先度1（基本方針）】同居人の声の遮断 ＞ 重複時の非言語音保持**: 同居人が喋っていない（背景が静かな）時は、自分の咳・伸び・あくび・ため息などの非言語音声を時間制限なく自然に通します。一方で、**「自分の非言語音」と「同居人の話し声」がぶつかって分離が困難な場合は、同居人の声をVCに漏らさないことを最優先とし、その瞬間の伸びやあくびが削れることを許容**します（Main DNN の他者音声検知ヘッド $p_{\text{interferer}}$ により、後ろで同居人が喋っている時はゲートを閉鎖ロックし、伸びの途中で同居人が喋り始めた場合も即座に閉鎖・ロックします）。
  * **【優先度2（拡張仮案A）】帯域別ゲート $\alpha(t, b)$ による部分救済**: 基本方針（優先度1）の実装後、もし「同居人と被った時の伸びの存在感ももう少し残したい」となった場合は、ゲートを周波数帯域ごとに分割し、同居人の声が乗る中音域は閉じたまま、自分の音が `+15 dB` 以上勝っている低域・高域だけを開く方式を試します。
  * **【優先度3（拡張仮案B）】局所周波数マスクを用いた重複データの重点学習**: さらにMain DNN自体の分離限界を時間-周波数ビン単位で引き上げたい場合の仮案として、局所SIRマスク損失を導入します。

## 2. BubbleMic のコア設計（4つの柱）

本プロジェクトでは、以下の4つの設計柱によって**「打鍵音と同居人の声は消えるのに、自分の咳や伸び・笑い声は自然に通る」**システムを構築します。

1. **並列サイドチェイン構成（Main Path: 自分専用統合DNN ＋ Sidechain Path: 汎用NR連動の削りすぎ救済ゲート）**
   * **Main Path（本線）** では、ファインチューニング済みの単一DNNがマイク入力から「打鍵音・環境ノイズ」と「同居人の声」を一括で消去し、自分の声と非言語音 $Y_{\text{dnn}}$ を抽出します。直列に2つのモデルを繋がないため、遅延の加算や前段ノイキャンによる息成分の消失が起きません。
   * **Sidechain Path（並列補助経路）** では、同じSTFT設定で動く素の汎用ノイキャンを通した信号 $Y_{\text{nr}}$（打鍵音のみ除去された人間の声）を監視し、**「同居人が喋っていない（Main DNN の他者音声検知ヘッド $p_{\text{interferer}}$ が低い）ときに、口元の大きな生体音をMain DNNが誤って削り落としてしまった瞬間」**だけ $Y_{\text{nr}}$ をブレンドして非言語音を救済します。
2. **公式学習済みモデル準拠の遅延設定（アルゴリズム遅延 40ms / 実測 60〜75ms）**
   * DiscordのPing（約50ms）と合わせても片道110〜125ms（会話で違和感のない150ms以下）に収まるため、STFT設定を変更せず公開学習済み重みをそのまま初期値として活用します。**GTCRN（16kHz）はオフライン検証専用**とし、リアルタイム運用は **DeepFilterNet3（48kHz、先読み2フレーム込み40ms）** のみで行います。
3. **「放置録音による本物の同居人会話データ」を活用した空間×声道ファインチューニング**
   * 同居人が部屋で友人と喋っている時に自分が無言のままマイクを録音しっぱなしにしておくことで、スピーカー再生では再現できない**「自分のマイクで集音された本物の同居人・友人の会話と部屋残響」**をそのまま消去対象（Noiseデータ）として収集・学習させます。
   * デスク真横の会話をスコープ外とすることで、消去対象を「部屋の残響を伴う遠方の他人声」に統一でき、声紋が崩れる自分の咳・伸び・ため息を「口元の直接生体音」としてMain DNNが削らずに残せるようになります。
4. **ハードウェア（単一指向性マイクの口元配置）との相乗効果**
   * ソフトウェア処理に加え、机置き（口から40cm）のマイク配置から「単一指向性マイクの口元5cm配置（または単一指向性ブームマイクの口元2〜3cm固定）」へ変更することで、物理的な信号対妨害音比（SIR）を机置き比で `20〜25 dB` 改善し、入力段階から高い分離有利性を確保します。

```text
~/bubble-mic/
├── README.md

│   ├── 01_architecture.md          # システム・並列サイドチェイン信号処理設計

│   ├── raw_self_speech/            # 自分の通常発話録音（20〜30分）
│   ├── raw_self_nonverbal/         # 自分の咳・伸び・笑い声・ため息録音（5〜10分）
│   ├── raw_passive_roommates/      # 同居人・友人が会話中に放置録音した実環境バックグラウンド音声
│   ├── raw_desk_transients/        # 自分のキーボード打鍵音・マウスクリック・机衝撃音
│   ├── raw_room_rirs/              # 実部屋で測定したインパルス応答・スピーカー補助録音
│   ├── raw_room_tone/              # 無音時の部屋の定常音（ノイズフロア整合用）
│   └── eval_semi_real/             # 評価専用の個別録音（学習データとは別セッション/別話者）
├── src/
│   ├── dataset/                    # 実録ノイズ＆RIR畳み込み動的ミキシング（フレーム単位ラベル出力）
│   ├── models/                     # GTCRN / DeepFilterNet3 ファインチューニング定義（p_interferer ヘッド含む）
│   ├── dsp/                        # 前段HPF・過剰抑制検知サイドチェインゲート（フェイルセーフ制御）
│   ├── eval/                       # Shadow Filtering ベースの評価スクリプト
│   └── engine/                     # ONNX Runtime / libdf リアルタイム推論エンジン（ASRC含む）
└── checkpoints/                    # 学習済みモデル
```
